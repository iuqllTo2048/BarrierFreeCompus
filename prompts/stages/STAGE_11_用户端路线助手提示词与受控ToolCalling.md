# Stage 11：用户端路线助手提示词与受控 Tool Calling

## 目标

只改用户端路线助手，不改治理统计，不接入 RAG。模型负责自然语言理解、受控选择工具和解释；校园地点、设施、障碍、路线与风险事实仍由业务数据库和自建 A* 决定。

## 已确认需求

- 服务普通学生、临时受伤者、轮椅用户、推车或行李用户。
- 支持路线规划、最多三条路线比较、推荐理由、最近无障碍设施、路线风险、生效障碍查询和障碍上报草稿。
- 缺起点或终点必须追问；地点歧义最多展示三个候选，不自行猜测。现有基础别名兼容保留，统一的数据驱动模糊检索暂缓。
- 默认行动方式来自用户资料；本轮文字与界面冲突时以文字为准，并明确说明切换。
- 推荐优先级：安全可达 > 无楼梯 > 低坡度 > 低风险 > 距离。没有完全无障碍路线时返回风险最低的可达方案并醒目警告。
- 回答采用推荐结论、路线概览、推荐理由、风险提醒、沿途设施、替代路线；只在 LOW、UNKNOWN 或数据冲突时说明可信度。
- 同一会话可继承端点、行动方式、偏好、推荐路线及设施/障碍意图；重规划时说明改变条件。
- 写操作只能生成草稿，用户确认后走正常 REST 和管理员审核。
- 正式公共服务语气，温和耐心，不使用 emoji，不作绝对安全承诺。
- DeepSeek/OpenAI-compatible Provider 失败时保留基础路线结果并提示智能解释不可用。

## 实现边界

- 系统提示词存放于后端 classpath 资源，不提供网页编辑。
- 模型只能调用后端暴露的白名单工具；用户、数据集、会话和调用 ID 均由可信执行上下文固定。
- 每个参数由后端做长度、枚举、数据集状态、地点唯一性和路网连接校验。
- 单轮最多 8 次工具调用、最多 6 轮 Tool Calling；相同工具和参数禁止重复调用。
- 不开放 SQL、Shell、删除、角色、审核、配置、Demo 重置等工具。
- 不加入 RAG，不修改治理统计总结提示词。
- 用户端默认隐藏管理员维护的完整校园路网，允许用户手动显示；地图选点只临时显示可选地点。
- 路线比较卡保留最多三条，地图仅绘制当前选中的有效路线；点击路线卡切换地图路线。
- 管理员辅助节点“新道路节点”不得出现在用户端候选地点或地图选点中。
- 用户明确要求“经过/途经/先到再到”时，模型按原始顺序传入最多 3 个途经点；不得拆成多次路线 Tool 调用。
- 后端按途经点数量拆成相邻路段，复用现有单段 A*，再确定性合并为完整路线；模型不得生成或拼接地图坐标。
- 新路线异步计算期间保留上一条结构化路线，追问风险或确认路线时地图不得清空；新路线返回后地图自动适配完整折线视野。
- 每个路线 Profile 使用加权 Yen Top-K 从现有 A* 生成不同无环候选；优先返回三条真实路线，实际路网不足时允许少于三条，禁止复制路线凑数。

## 验收场景

1. 正常轮椅路线和三路线比较；
2. 缺少起点时追问；
3. 地点歧义时最多三个候选；
4. 文字行动方式覆盖界面并明确说明；
5. “换成临时受伤”继承端点并重新规划；
6. 查询最近无障碍卫生间；
7. 无完全无障碍路线时显示风险最低可达方案警告；
8. 提示词注入、SQL、角色或删除请求直接拒绝；
9. Provider 失败时保留 A* 与手工路线能力。
10. 用户路线页与智能助手初始不显示完整路网，开关可恢复显示；
11. 地图选点无需开启完整路网，选点期间只显示可选地点；
12. 多条路线卡可切换，但地图任一时刻只显示当前选中的路线。
13. “从 A 经过 B 到 C”只产生一次路线 Tool 调用，后端日志显示 1 个途经点、2 个分段，地图显示 A→B→C 的合并折线；
14. 对已规划路线继续追问风险时，不重新计算也不清空地图路线。
15. 路网存在三条可达替代路径时返回最短、无障碍优先、综合三张不同路线卡，默认选中确定性推荐项；逐卡点击时地图只显示对应折线。
