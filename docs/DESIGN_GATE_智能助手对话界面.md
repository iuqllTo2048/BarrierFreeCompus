# Design Gate — 智能路线助手对话式界面（方案三细化）

> 状态：历史 Design Gate 留档。对话 + 地图方向已经落地，但本文中的组件拆分名称和布局比例属于当时方案，不代表当前源码结构；实现事实以 `UserAssistantView.vue`、`CampusMap.vue` 和 `docs/AGENT.md` 为准。
> 上游约束：`AGENTS.md`、`docs/DESIGN_DIRECTION.md`、`docs/DESIGN_SYSTEM.md`、`.agents/skills/barrier-free-ui/SKILL.md`。

## 1. 背景与目标

组员反馈：智能路线助手页 UI 应更接近市面上"干净对话框"风格，明显突出"这是一个智能体"。

目标：把现有"表单式"助手页改造成**对话式**界面，让 AI 智能体成为视觉与交互核心；同时保留地图展示路线结果，不改后端、不换技术栈。

## 2. 必须遵守的约束

- Vue 3 + Element Plus；不新增 Tailwind/shadcn/其它 UI 框架。
- 用户端地图与寻路是核心，但助手页允许"对话为主、地图为辅"的布局。
- 使用 `DESIGN_SYSTEM.md` 语义 Token；深青绿主色；禁止紫色渐变、玻璃拟态泛滥、Bento Grid、霓虹发光、巨型营销 Hero。
- 风险/状态不能只靠颜色；必须文字、图标、线型或标签至少两种表达。
- 键盘可达、可见焦点、`aria-live`；尊重 `prefers-reduced-motion`。
- 深色模式跟随 `data-theme` 语义 Token，不做简单反色。

## 3. 页面布局（桌面端）

```text
┌──────────────────────────────────────────────────────────────┐
│ 助手身份条：图标 · 无碍智行·路线助手 · 状态(在线/降级) · 新建会话 │
├───────────────────────────────┬──────────────────────────────┤
│ 对话主区（约 58%）              │ 地图区（约 42%）              │
│  · 空态：欢迎语 + 建议问题       │  · 路线结果高亮/设施/障碍       │
│  · 用户消息（右对齐气泡）        │  · 地图上方：行动方式、数据集    │
│  · 助手回复（流式 + 工具时间线）  │    （轻量选择，不占对话空间）    │
│  · 路线结果卡片 / 草稿确认卡     │                              │
│  · 底部输入区 + 快捷问题         │                              │
└───────────────────────────────┴──────────────────────────────┘
```

- 身份条让用户第一眼知道"这是智能体"，并给出当前 AI 可用状态（在线 / 降级 / 关闭）。
- 行动方式与数据集从表单移到地图区轻量控件，对话区保持干净。

## 4. 对话消息设计

| 元素 | 视觉 |
|---|---|
| 用户消息 | 右对齐，`--color-surface-muted` 圆角气泡 |
| 助手回复 | 左对齐，浅底或无边，流式光标（SSE delta 已有） |
| 工具进度 | 助手消息上方内嵌小时间线：识别地点 → A* 计算 → 核对设施/障碍 → 比较风险 |
| 路线结果 | 卡片化嵌入对话（复用现有路线卡片样式） |
| 上报草稿 | 确认卡（复用现有草稿确认交互） |
| 错误/降级 | 助手气泡内错误文案 + 顶部状态条提示"模型不可用，使用规则回复" |

## 5. 组件改动清单

**新增**
- `AssistantIdentityBar.vue`：身份 + AI 状态 + 新建会话。
- `AssistantMessageList.vue`：消息气泡列表、自动滚动、工具时间线渲染。
- `AssistantComposer.vue`：底部输入区（Enter 发送 / Shift+Enter 换行）+ 快捷问题 chips。

**改造**
- `UserAssistantView.vue`：重组为身份条 + 对话主区 + 地图区；对话状态（发送中、空态、错误态）。
- 复用：`CampusMap.vue`、现有路线卡片/草稿卡样式、`tool-timeline` 样式、`agent-api` 流式逻辑。

**不改**：后端 AgentService / SSE 协议 / 白名单 Tool / 数据结构。

## 6. 交互细节

- 流式输出自动滚动到底部；用户向上滚动时暂停自动滚动。
- 发送中禁用输入与发送按钮；支持连续追问（同一会话）。
- 新建会话：清空消息列表并重新创建会话（`createConversation`）。
- 空态：欢迎语 + 3~4 个建议问题（如"从知行楼到图书馆，轮椅怎么走"）。
- 降级：不隐藏对话，顶部状态条 + 助手消息内说明，路线规划仍可用。

## 7. 可访问性

- 助手回复与工具状态使用 `aria-live="polite"` 播报。
- 输入框有 label，发送按钮有可见文字；图标按钮有 `aria-label`。
- 对话区 Tab 顺序与视觉一致；焦点环使用 `--color-focus`。
- 消息对比度满足正文 4.5:1；风险文本不单独依赖颜色。

## 8. 响应式

- 桌面（≥1024px）：对话 + 地图并排。
- 移动（<768px）：地图为主，对话以底部抽屉/全屏切换；输入区固定底部并有安全区；主要点击区 ≥44px。

## 9. 历史验收目标

1. 打开智能路线助手，第一眼是干净的对话界面与明确的智能体身份。
2. 发送"从知行楼到图书馆，轮椅怎么走"：流式输出、工具时间线、路线卡片、地图高亮完整出现。
3. 发送中不可重复提交；输入支持 Enter 发送 / Shift+Enter 换行。
4. 降级时显示状态条，手工路线仍可用。
5. 键盘可完成全流程；屏幕阅读器能听到助手回复播报。
6. 深色模式、375px 移动端布局正常；无 JS 错误，vitest/typecheck/lint/build 全绿。

## 10. 边界与风险

- 只改前端展示层，不动 AI 协议与后端逻辑。
- 不引入新依赖、不换框架。
- 移动端重排工作量最大，本 Gate 先保证桌面 + 375px 可用。
