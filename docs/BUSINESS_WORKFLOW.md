# BUSINESS_WORKFLOW.md — 用户与管理员业务闭环

## 用户业务

- 每次成功调用路线规划 API 都会写入当前用户的路线历史；收藏引用历史记录和具体 Profile，删除历史会级联删除对应收藏。
- 用户资料保存默认行动方式、避楼梯、距离/坡度/宽度权重及设施偏好，权重限制为 `0.5–2.0`。
- 设施详情包含所属建筑、楼层、开放状态、更新时间、来源、可信度和可空 `photo_url`。同一用户对同一设施只有一条评分，可更新；评论和补充建议保留审计来源。

## 障碍上报与可信度

用户上报包含 GCJ-02 地图坐标、障碍类型、描述和预计持续小时数，不要求图片。

1. 首次单用户上报保存为 `LOW / PENDING / inactive`，审核前不影响路线。
2. 同一用户在配置时间窗口和半径内重复提交同类障碍时返回 HTTP 409。
3. 不同用户的同类型、相近时间和位置上报会关联到同一主记录，相关记录升级为 `MEDIUM / NEEDS_VERIFICATION`，但仍不生效。
4. 管理员审核 `APPROVED` 后才设为生效；只有勾选“实地核验”才能授予 `HIGH`。
5. Scheduler 定期停用已到期障碍；路线仓库同时实时判断 `ends_at`，避免调度间隔内使用过期数据。

默认匹配半径为 50 米、时间窗口为 24 小时。GCJ-02 数据以 SRID 0 保存，校园尺度邻近计算使用经纬度近似换算；正式采集时应进一步校准。

## 管理治理

- 管理员可查看总览、地图障碍审核、设施建议、用户状态、审计日志和系统设置。
- 禁用用户会撤销其刷新令牌；JWT 过滤器每次请求校验数据库启用状态，因此现有访问令牌也立即失效。
- 建筑、入口、节点、设施使用 `active` 软停用，道路使用 `INACTIVE`；上报和审计不物理删除。
- Demo 安全重置只允许 `is_demo=true` 的数据集，清理其评分、评论、建议、路线历史和用户上报，并恢复 Demo 种子对象启用状态；Formal 数据集请求会被拒绝，审计日志保留。

## 权限边界

- USER 与 ADMIN 均可使用用户业务和路线功能。
- `/api/admin/business/**` 仅 ADMIN 可访问。
- 用户只能访问自己的历史与收藏；收藏和删除操作都同时校验当前用户 ID。
- 用户不能自行让障碍生效、授予 HIGH、禁用用户、修改设置或执行 Demo 重置。
