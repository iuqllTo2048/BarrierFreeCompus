# DESIGN_SYSTEM.md — BarrierFreeCampus 设计系统

> 状态：Design Gate 已确认。适用于后续所有用户端与管理端页面；`docs/DESIGN_DIRECTION.md` 仍是本规范的上游约束。

## 1. 设计原则

**静谧导览**：以地图和路线为中心的校园公共服务工具。界面应清晰、可信、友好而克制；轻科技感只来自路线、数据层级和反馈，不使用紫色渐变、霓虹、玻璃拟态、Bento Grid 或营销式巨型 Hero。

- 用户端优先级：地图与路线 → 起终点和行动模式 → 风险与设施 → AI 辅助。
- 管理端优先级：地图与数据治理 → 状态和风险 → 图表 → 表格。
- 所有重大状态必须同时使用颜色、文字、图标或线型中的至少两种表达。

## 2. 语义色彩

所有实现使用语义 Token；不得在页面中散落硬编码颜色。

| Token | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `--color-bg` | `#F6F8F7` | `#101918` | 页面背景 |
| `--color-surface` | `#FFFFFF` | `#172321` | 卡片、抽屉、面板 |
| `--color-surface-muted` | `#EDF3F1` | `#20302D` | 次级区域、选中底色 |
| `--color-text` | `#18332D` | `#F1F7F5` | 主文本 |
| `--color-text-secondary` | `#52645F` | `#B9CAC5` | 次级文本 |
| `--color-border` | `#D5E2DE` | `#35504A` | 分隔线与边框 |
| `--color-primary` | `#0F766E` | `#36B8A4` | 品牌、主操作、无障碍路线 |
| `--color-primary-hover` | `#0B625C` | `#65CCBC` | 悬停与强调状态 |
| `--color-secondary` | `#176B82` | `#5CB8CE` | 综合路线、辅助数据 |
| `--color-danger` | `#B42318` | `#F97066` | 高风险、不可通行 |
| `--color-warning` | `#B54708` | `#FDB022` | 警告、待注意 |
| `--color-success` | `#067647` | `#47CD89` | 低风险、已验证、完成 |
| `--color-unknown` | `#667085` | `#98A2B3` | 未知、未核验、最短路线 |
| `--color-focus` | `#0B6E99` | `#74C8E5` | 键盘焦点环 |

- 灾害/封路等风险使用 `--color-danger`，配风险图标和明确短文案。
- 可信度与数据来源在颜色之外必须保留标签文字；UNKNOWN 使用灰色和“未核验/未知”文本。
- Element Plus 主题变量映射到主色、语义色、边框和圆角 Token，不覆盖组件的语义行为。

## 3. 排版、空间与组件基础

- 字体：`"Microsoft YaHei UI", "PingFang SC", "Noto Sans SC", Arial, sans-serif`；数值可使用 `"Cascadia Mono", Consolas, monospace` 作为局部回退。
- 字号：12px 辅助说明、14px 正文/表单、16px 强调正文、20px 区块标题、24px 页面标题、32px 仅用于首页或地图关键状态。
- 字重：400 正文、500 控件与标签、600 标题、700 关键数值；不使用营销式超大粗体标题。
- 间距基数为 4px，常用阶梯为 4/8/12/16/24/32/48px。页面内边距：桌面 24px，平板 20px，手机 16px。
- 圆角：8px 用于输入与小型控件，12px 用于面板与抽屉；避免大面积胶囊形控件。
- 阴影仅用于地图浮层、抽屉和模态层：浅色使用低不透明度的 0 8px 24px 阴影；普通卡片优先靠边框和背景分层。
- 所有可操作控件应有至少 2px 的可见焦点环；图标按钮提供 `aria-label`，有可见文字的装饰图标设为 `aria-hidden`。

## 4. 用户端地图与路线

### PC（≥1024px）

- 使用 64px 轻量顶栏：左侧文字标识“无碍智行”，中部为核心导航，右侧承载个人入口与主题切换；不使用固定左侧全局导航。
- 地图是主画布。左侧为约 360px 的路线控制面板，包含起终点、行动模式与偏好；右侧路线结果面板按需展开，避免长期遮挡地图。
- 路线结果先给推荐结论，再给距离、预计耗时、风险摘要、绕行原因和设施；复杂成本明细默认折叠。

### 移动端（<768px）

- 地图保持页面主区域；表单和结果使用底部抽屉，不将桌面侧栏机械缩窄。
- 抽屉有清晰的展开层级、拖拽替代按钮和足够底部安全区；主要点击区不小于 44px。
- 起终点、行动模式和偏好按“先路线、后细化”的顺序呈现，避免长表单。

### 路线视觉

| 路线 | 地图线型 | 卡片表达 |
|---|---|---|
| 最短路线 | `--color-unknown` 灰色 4px 虚线 | “最短路线” + 风险/楼梯状态 |
| 无障碍优先 | `--color-primary` 深青绿 6px 实线 | “无障碍优先” + 约束满足与绕行原因 |
| 综合推荐 | `--color-secondary` 蓝绿 4px 实线 | “综合推荐” + 推荐标签与取舍摘要 |

起终点、障碍、设施和路线图例均使用同一套线性 SVG 图标风格。路线选择不能只靠颜色；卡片、图例和地图悬浮提示同时提供名称与状态。

## 5. 管理端、图表与深色模式

- 管理端使用紧凑侧栏或顶部导航，主体为“地图主画布 + 可收起数据检查器”。选中道路、设施或障碍后，同步显示可信度、来源、影响范围与审核操作。
- 表格是地图对象的明细和批量操作入口，不应替代地图治理视图。
- ECharts 每张图回答一个问题：障碍趋势使用折线图、可信度与类型使用条形/堆叠条形图、空间影响通过地图叠层呈现。默认色序：主色、辅助色、成功、警告、危险、未知。
- 深色模式替换全部语义 Token，保留边框、文本、路线和焦点可辨性；不做简单反色或赛博朋克处理。

## 6. 交互与可访问性

- 常规悬停、按下、抽屉和卡片状态变化约 200ms；路线绘制和地图选中可使用轻量动画。`prefers-reduced-motion` 下直接呈现最终状态。
- Tab 顺序必须与视觉阅读顺序一致；固定顶栏、抽屉和浮层不得遮挡焦点。
- 输入控件有可见标签、错误说明和保留输入值；图标操作有文本替代。
- 路线风险、审核状态、图表分类均不能仅依赖颜色；对比度满足正文 4.5:1，重要非文本控件至少 3:1。
