# 无碍智行 v1.0 用户与管理员详细使用说明书

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 产品名称 | BarrierFreeCampus（无碍智行） |
| 版本 | v1.0 / `1.0.0` |
| 本地访问地址 | `http://localhost:8080` |
| 适用角色 | 校园用户、系统管理员、比赛演示人员 |
| 地图坐标 | GCJ-02 |
| 核心路线 | 自建校园路网 + 可解释 A*，不是高德路线规划 |

本说明书按页面实际功能编写。界面中的路线、风险和统计仅用于项目演示与辅助判断，不替代现场安全确认、医疗建议或正式无障碍认证。

## 2. 开始使用

### 2.1 确认系统已经启动

浏览器打开 `http://localhost:8080`。若无法访问，管理员可在项目根目录执行：

```powershell
docker compose ps
docker compose logs --tail 100 backend
```

`db` 和 `backend` 应显示 healthy；`http://localhost:8080/actuator/health` 应返回 `{"status":"UP"}`。

### 2.2 本地演示账号

| 角色 | 用户名 | 密码 | 默认进入页面 |
|---|---|---|---|
| 校园用户 | `demo_user` | `Demo@12345` | 路线规划 |
| 管理员 | `demo_admin` | `Admin@12345` | 地图数据 |

演示账号只能用于本地比赛环境。公开部署前必须替换或停用。

### 2.3 登录、主题与导航

1. 在登录页输入用户名和密码，点击“登录”。
2. 登录后，顶栏右侧显示当前用户名和角色。
3. 点击太阳/月亮按钮切换浅色或深色；刷新页面后主题仍会保留。
4. 桌面端直接使用顶栏导航；窄屏端点击菜单按钮展开导航。
5. 点击“退出登录”结束当前会话。

用户可见导航：路线规划、用户服务、智能路线助手。管理员除此之外还能进入地图数据、治理工作台和治理洞察。

## 3. 校园用户操作说明

### 3.1 规划校园路线

进入“路线规划”。桌面端左侧是设置区、中央是地图、右侧是结果区；移动端通过“路线设置”和“路线结果”按钮展开对应面板。

#### 选择数据集和端点

1. 在“数据集”中选择 `YUNLU_DEMO_V1`。
2. 起点和终点可以直接从下拉列表选择。
3. 也可以点击起点或终点旁的“从地图选择”，再点击地图上的道路节点。
4. “交换起点与终点”会清除旧结果并交换方向。

建议演示：选择“知行楼北（N-02）”到“图书馆北（N-03）”，便于观察楼梯捷径与轮椅绕行。

#### 选择行动方式

| 选项 | 适用情况 | 主要影响 |
|---|---|---|
| 轮椅出行 | 轮椅使用者 | 楼梯始终不可通行 |
| 拐杖辅助 | 使用拐杖 | 楼梯和坡度成本明显提高 |
| 临时受伤 | 术后、扭伤等 | 偏向更平缓和稳定的道路 |
| 推车/大件行李 | 婴儿车、手推车、行李 | 楼梯成本高，偏向宽路 |
| 普通步行 | 普通行人 | 允许楼梯，但仍解释风险 |

时段选择“白天”或“夜间”。夜间规划会额外考虑道路照明等级。

#### 设置路线偏好

- 避开楼梯：优先将楼梯当作不可选偏好；若普通步行等模式完全无路，系统可能返回明确标注的风险最低可达方案。轮椅的楼梯禁令不会放松。
- 距离权重：越高越强调距离成本。
- 坡度权重：越高越不愿经过陡坡或未知坡度。
- 宽度权重：越高越不愿经过狭窄或宽度未知道路。
- 休息点偏好：缺少休息设施的路段会增加成本。
- 无障碍卫生间偏好：缺少相应设施的路段会增加成本。

权重允许范围为 0.5–2.0。偏好改变的是路线比较，不代表设施一定开放；仍应查看沿途设施状态和可信度。

#### 查看规划结果

点击“规划三类路线”。系统分别计算最短、无障碍优先和综合路线；如果两类路线使用完全相同的道路序列，会合并展示，所以结果卡片可能少于三张。

| 路线 | 地图表现 | 关注点 |
|---|---|---|
| 最短路线 | 灰色虚线 | 优先减少距离，可能包含更多风险 |
| 无障碍优先 | 深青绿实线 | 更重视坡度、楼梯、宽度、路面和未知数据 |
| 综合路线 | 蓝绿实线 | 在距离与无障碍成本之间折中 |

点击不同路线卡片可切换地图高亮。结果区会显示：

- 总距离和预计时间；
- 低/中/高/未知风险文字；
- 楼梯级数和坡度汇总；
- 沿途设施与生效障碍；
- 数据可信度；
- 距离、坡度、楼梯、宽度、路面、照明、障碍、不确定性、设施偏好的成本明细；
- 本次遵守的约束和风险警告。

风险不会只靠颜色表达。预计时间是演示估算，不是实时导航承诺。

#### 收藏路线

1. 先完成一次规划并选中目标路线。
2. 点击“收藏当前路线”。
3. 在弹窗中填写便于识别的名称并确认。
4. 前往“用户服务 → 收藏路线”查看。

每次成功规划都会自动进入路线历史。

### 3.2 查看和反馈无障碍设施

进入“用户服务 → 设施详情”。可从路线地图点击设施自动跳转，也可以在设施列表中选择。

设施详情包含名称、类型、所属建筑、楼层、开放状态、来源、可信度、说明和更新时间。用户可以：

1. 选择 1–5 分提交评分；再次评分会更新自己的原评分。
2. 在评论框填写实际通行体验并发布。
3. 选择“信息纠正”“新增设施”或“维护建议”，填写说明后提交。

评论和建议不会直接修改地图，管理员会在治理工作台处理建议。

### 3.3 上报临时障碍

进入“用户服务 → 障碍上报”。

1. 选择当前 Demo 数据集。
2. 选择障碍类型，例如楼梯、施工、临时封闭、积水、陡坡、狭窄、车辆占道、电梯停运、入口关闭或路面损坏。
3. 填写简洁标题和事实描述。
4. 设置预计持续小时数。
5. 点击地图选取坐标，确认经纬度已经写入表单。
6. 点击“提交上报”。

提交后的首次单用户上报为 LOW、待审核且未生效，不会立即改变路线。不同用户在相近时间和位置上报同类障碍时，可升级为 MEDIUM/待核验，但仍需管理员审核。

“我的上报”可查看待审核、待核验、已通过或已拒绝状态。只有已通过、生效且未过期的障碍才参与路线计算。

### 3.4 管理历史、收藏和个人偏好

在“用户服务”中：

- 路线历史：查看起终点、行动方式和时间；可收藏或删除。删除历史会同时删除依赖该历史的收藏。
- 收藏路线：查看收藏名称和 Profile；可取消收藏。
- 个人中心：保存默认行动方式、避楼梯、三个权重、休息点和无障碍卫生间偏好。

个人偏好会在下次打开路线规划页时自动加载。若资料接口暂时失败，路线页仍可使用页面默认值。

### 3.5 使用智能路线助手

进入“智能路线助手”，选择数据集和行动方式，在输入框描述需求。推荐示例：

```text
从图书馆到体育与健康中心，轮椅怎么走？
当前校园有哪些生效障碍？
上报图书馆附近道路积水
```

发送后，页面会按顺序展示请求状态、地点搜索、A*、设施/障碍查询、路线比较等 Tool 进度，并以流式文字返回说明。地图上的结构化路线与风险数据来自后端 A*，不是模型自行编造。

若只识别到一个地点，助手会要求补充另一个端点；不会猜测不存在的路线。

障碍请求只生成两小时有效的草稿。请核对位置、类型和描述，再点击确认提交；正式记录仍是待审核状态。助手不能执行 SQL、Shell、删除道路、修改角色、审核或重置 Demo。

外部 AI 关闭时使用本地确定性 Mock；限流或异常时会提示降级，手工路线规划仍可使用。

## 4. 管理员操作说明

### 4.1 地图数据工作区

进入“地图数据”。顶部选择数据集，中央为地图，工具栏用于选择或创建对象，右侧检查器用于填写数据。

#### 选择和搜索对象

1. 保持“选择对象”模式。
2. 点击地图 Marker/道路，或在搜索框输入名称、编号。
3. 右侧检查器会显示所选对象数据。
4. 对支持编辑的节点和道路，可修改后保存；其他对象按当前页面提供的新增与状态管理能力操作。

#### 新增节点

1. 点击“新增节点”。
2. 点击地图确定坐标，也可在表单中填写经纬度。
3. 填写数据集内唯一的外部编号和节点名称。
4. 选择交叉点、入口、途经点或设施连接点。
5. 确认节点状态，点击保存。

节点停用后不能作为有效路线端点。

#### 新增或编辑道路

1. 点击“新增道路”，或选择已有道路进行编辑。
2. 填写唯一道路编号、名称、起点节点和终点节点。
3. 如道路不是直线，在“折线中间点”中每行填写一个 `经度,纬度`。
4. 填写距离，并选择坡度、宽度、路面、照明、风险和状态。
5. 设置是否双向、是否包含楼梯及楼梯级数。
6. 保存后重新规划路线验证影响。

道路状态中，只有 ACTIVE 可通行；INACTIVE、CLOSED、BLOCKED 都不会进入正常搜索。不要用“高风险”代替“封闭”：高风险仍可能通行，封闭状态才是硬阻断。

#### 新增建筑、入口、设施和障碍

1. 在工具栏选择对应类型。
2. 点击地图确定位置；建筑演示编辑器会根据当前操作生成所需几何。
3. 填写外部编号、名称/标题、类别或类型。
4. 入口和设施可关联所属建筑，并设置开放状态。
5. 设施可填写楼层与说明。
6. 障碍需选择类型、审核状态、说明和是否立即启用。

用于正式治理的用户上报仍建议通过“治理工作台”审核，不要仅靠地图编辑器模拟审核闭环。

#### 数据集与 GeoJSON

- 启用/停用：停用后普通用户看不到该数据集，管理员仍可管理。
- 导出 GeoJSON：下载当前数据集的节点、道路和设施。
- 导入 GeoJSON：只允许 Demo，文件必须是 FeatureCollection，`datasetId` 匹配且 `coordinateSystem=GCJ02`；道路引用的端点必须存在。

导入为校验后的幂等更新，不接受把 GCJ-02 错误标成 WGS84。所有管理写操作会记录审计日志。

### 4.2 治理工作台

进入“治理工作台”。

#### 数据总览

查看用户、生效障碍、待审核/核验、启用设施、路线规划和待处理建议数量。优先处理区用于快速定位当前治理任务。

#### 审核障碍

1. 打开“障碍审核”，从左侧队列选择上报。
2. 核对类型、描述、位置、提交时间、可信度和关联上报。
3. 需要补充时填写审核备注。
4. 若确实完成现场核验，勾选“实地核验”。
5. 点击“审核通过”“要求核验”或“拒绝”。

审核通过会立即影响下一次路线规划。只有“审核通过 + 实地核验”才能授予 HIGH；不能仅凭模型文本或单人上报设置 HIGH。

#### 用户管理

“用户管理”可启用或禁用账号。禁用后该用户的 Refresh Token 会撤销，现有 Access Token 在下一次请求时也会因数据库状态检查而失效。

不要在演示中禁用当前正在使用的管理员账号。

#### 设施建议

查看用户提交的信息纠正、新增设施或维护建议，结合地图事实选择“采纳”或“拒绝”。状态处理本身不会自动创建新的地图对象；需要时再前往地图数据页维护。

#### 审计与智能体日志

- 审计日志：查看操作者、动作、目标对象、说明和时间。
- 智能体调用日志：查看用户、Provider、模型、成功状态、耗时、Tool 摘要、Request ID 和脱敏错误。

日志不会显示 API Key、隐藏思维链、任意 SQL 或完整异常堆栈。

#### 系统设置

可维护障碍匹配半径、时间窗口、过期调度等白名单设置。保存前确认值的单位和范围；设置只影响后续业务，不会修改历史审计。

### 4.3 治理洞察

进入“治理洞察”。

1. 选择数据集。
2. 按需要选择建筑、开始/结束日期、设施类型、障碍类型和可信度。
3. 点击“应用筛选”。
4. 查看概要、障碍地图、建筑评分、设施分布、障碍趋势、路线风险和数据可信度。

点击建筑排名会定位地图并在检查器显示入口、电梯、卫生间、道路可达性、障碍影响和数据完整度分项。点击障碍 Marker 会显示类型、可信度和治理权重。

“导出当前 CSV”只导出当前筛选范围，文件使用 UTF-8 BOM，并防止公式注入。“生成治理建议”只解释已经计算的统计，不会执行地图修改；AI 关闭或失败时返回规则摘要。

空数据会显示 0 或“无数据”，不会自动填充模拟趋势。

### 4.4 安全重置 Demo

“安全重置 Demo”是会改变数据的管理员操作。

1. 确认当前选择的是 `YUNLU_DEMO_V1`。
2. 点击“安全重置 Demo”。
3. 阅读二次确认，确认确实需要清理当前 Demo 业务数据。
4. 点击“确认重置”；如仅检查功能，请点击取消。

重置会：

- 删除当前 Demo 的评分、评论、建议、路线历史和用户上报；
- 恢复 Demo 数据集启用状态和种子对象启用状态；
- 恢复楼梯绕行、陡坡冲突、动态封路、UNKNOWN 数据和设施偏好五类关键场景；
- 保留审计日志。

后端会锁定并验证 `is_demo=true`。Formal 数据集会被拒绝，不会进入删除或恢复 SQL。重置不同于 `docker compose down -v`；后者会删除整个数据库卷，不能作为普通重置方式。

## 5. 推荐比赛演示脚本

### 5.1 用户价值演示

1. USER 登录，切换一次深色模式。
2. 选择知行楼北到图书馆北，先用普通步行规划，说明最短路线可能经过阶梯捷径。
3. 切换轮椅重新规划，说明楼梯是硬约束且路线自动绕行。
4. 展开成本明细和风险警告，说明 UNKNOWN 不会被伪装成安全。
5. 收藏路线并展示历史。

### 5.2 治理闭环演示

1. USER 在图书馆附近上报道路积水。
2. ADMIN 打开治理工作台，说明首次上报审核前不影响路线。
3. 审核通过后回到用户路线页重新规划。
4. 展示路线变化、地图障碍和审计日志。

### 5.3 技术亮点演示

1. 在地图数据页展示节点、道路属性与 GeoJSON。
2. 强调高德只负责底图，自建路网 A* 负责路线。
3. 在智能助手输入路线需求，展示白名单 Tool 与 SSE。
4. 在治理洞察展示地图—建筑评分—图表联动和 CSV。
5. 说明 AI 关闭或限流时，手工路线、审核和统计不受影响。

## 6. 常见问题与处理

| 现象 | 可能原因 | 处理方法 |
|---|---|---|
| 无法登录 | 账号错误、用户被禁用、服务未启动 | 核对账号；管理员检查用户状态；查看 backend health |
| 用户页没有数据集 | Demo 被停用 | ADMIN 在地图数据页重新启用数据集 |
| 地图空白但页面正常 | 高德 Key、安全密钥或域名白名单错误 | 检查 `.env`、`/_AMapService` 和浏览器网络请求 |
| 只显示一两条路线 | 多个 Profile 的边序列相同 | 查看路线卡片的等价 Profile，不是计算丢失 |
| 轮椅没有路线 | 起终点断开或只有楼梯通道 | 更换端点，检查道路状态和阻断障碍；不要放松轮椅楼梯约束 |
| 上报后路线没变化 | 尚未审核、未激活或已过期 | ADMIN 检查审核状态和有效期 |
| AI 提示服务繁忙 | Provider 限流或超时 | 稍后重试或关闭 AI；使用手工路线继续演示 |
| 401 | Access/Refresh 过期或 Cookie 配置错误 | 重新登录；本地 HTTP 确保 `SECURE_COOKIE=false` |
| 403 | 当前角色无权限 | 使用 ADMIN；不要通过前端绕过权限 |
| CSV 中文乱码 | 使用不支持 BOM 的导入方式 | 用 Excel/WPS 正常打开或按 UTF-8 导入 |
| Demo 重置被拒绝 | 当前是 Formal 或角色不是 ADMIN | 这是安全保护；不要通过 SQL 强行绕过 |

## 7. 数据与安全注意事项

- 不把 `.env`、JWT Secret、高德安全密钥或 AI Key 发到聊天、截图、Git 和日志。
- 高德 Web JS Key 会进入浏览器资源，应依赖正确域名白名单保护。
- 不把 GCJ-02 数据声明为 WGS84/EPSG:4326。
- 不直接修改已执行的 Flyway V1–V7；数据库结构变化应新增迁移。
- 正常停止使用 `docker compose down`，不要随意添加 `-v`。
- 用户上报、模型解释和 Demo 数据都不等于现场核验。
- 正式部署前应替换演示账号、启用 HTTPS、设置 `SECURE_COOKIE=true`，并配置数据库备份、日志、监控和限流。

## 8. 退出与停止系统

用户完成操作后点击顶栏“退出登录”。管理员需要停止本地系统时，在项目根目录执行：

```powershell
docker compose down
```

该命令保留 `postgres-data` 数据库卷。再次执行 `docker compose up -d` 即可恢复服务。
