## Stage 3 已实现

- 自建路网 A*：基于启用的 GCJ-02 数据集实时装载有向图，遵守单向道路，使用可采纳的缩放球面距离启发函数。
- 行动模式：`WHEELCHAIR`、`CRUTCH`、`TEMPORARY_INJURY`、`CART_LUGGAGE`、`WALKING`。
- 三类路线：分别计算 `SHORTEST`、`ACCESSIBLE`、`BALANCED`，按边序列去重并说明等价 Profile。
- 集中成本策略：距离、坡度、楼梯、宽度、路面、昼夜照明、道路风险、动态障碍、数据未知和设施偏好均由 `RouteCostPolicy` 管理并返回明细。
- 硬约束与降级：`BLOCKED` 和阻断型生效障碍立即不可通行；轮椅永不通过楼梯；普通避楼梯偏好无路时可返回带强警告的风险最低可达路线。
- 动态数据：每次规划重新读取道路、开放设施及已审核且在有效期内的障碍，无需重启服务。
- API：新增 `POST /api/routes/plan`，返回 GeoJSON、距离、估算时间、风险、楼梯、坡度、设施、障碍、可信度、成本、约束、警告和算法指标。
- 数据迁移：Flyway V5 将道路状态约束扩展为 `ACTIVE / INACTIVE / CLOSED / BLOCKED`，未修改历史迁移。
- 用户端：地图优先三栏规划界面，支持起终点下拉/地图选点、五类行动方式、昼夜、避楼梯和有限权重偏好；地图叠加三种非纯颜色路线样式，结果区展示风险、警告与成本解释。
- 管理端：道路状态选择增加 `BLOCKED`，保存后下一次规划立即绕行。
- 算法文档：`docs/ROUTING_ALGORITHM.md` 记录路网、启发函数、硬约束、成本构成、降级和 API 语义。

## 已知限制

- 当前路线输入以路网节点为起终点，尚未实现 GPS 定位、任意坐标吸附或逐步语音导航。
- 预计时间是按行动模式速度和楼梯级数计算的演示估算，不包含实时人流、天气或医疗个体差异。
- 设施和障碍按约 25 米的 GCJ-02 校园尺度邻近范围关联道路；正式数据采集后应改为明确的边关联或经校准的空间规则。
- Demo 数据均为 `DEMO_GENERATED / UNKNOWN`，不能作为真实通行安全保证。
- Stage 3 前端是路线交互骨架，尚未进行 Stage 8 的 Playwright 和多设备最终视觉验收。
- Node 26 非常规 LTS 风险继续保留；Docker 构建固定使用 Node 22 Alpine。

## 人工验收

1. 打开 `http://localhost:8080/user`，使用 `demo_user` 登录。
2. 选择“普通步行”，规划 Demo 默认起终点，确认地图和结果区出现最短、无障碍优先、综合路线；若路线重合，确认等价 Profile 被说明。
3. 切换“轮椅出行”，确认路线不包含楼梯；展开成本明细，确认距离、坡度、楼梯、宽度和障碍/未知均可解释。
4. 开启“尽量避开楼梯”、调整 0.5–2.0 权重、切换夜间，确认结果可重新规划且显示风险文字，不只依赖颜色。
5. 使用管理员进入地图数据管理，将演示道路状态改为 `BLOCKED`；返回用户端重新规划，确认无需重启即绕行。完成后把道路恢复为 `ACTIVE`。
6. 缩窄浏览器窗口并切换系统深色模式，确认地图在上、规划与结果面板在下，主要控件仍可键盘聚焦。
