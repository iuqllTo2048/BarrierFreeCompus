## Stage 4 已实现

- 用户服务：设施详情、评分、评论、设施补充建议、地图障碍上报、我的上报、路线历史、路线收藏和个人默认行动偏好。
- 路线历史：每次成功规划自动保存请求和结果快照，并返回 `historyId`；历史与收藏按当前用户隔离。
- 设施信息：卫生间等设施详情包含建筑、楼层、开放状态、更新时间、数据来源、可信度和可空图片地址。
- 障碍可信度：单用户 `LOW`；不同用户在配置半径/时间内同类上报升级为待核验 `MEDIUM`；同用户重复提交返回 409；审核前始终不生效。
- 审核闭环：管理员可通过、拒绝或要求核验；只有实地核验可以授予 `HIGH`，审核通过后立即影响下一次路线规划。
- 临时障碍：`ends_at` 作为 API `expiresAt`；Scheduler 自动停用到期障碍，路线查询仍实时检查有效期。
- 管理治理：总览骨架、地图障碍审核、设施建议处理、用户启停、审计日志、系统设置和 Demo 安全重置。
- 软删除：建筑/入口/节点/设施使用 `active`，道路使用 `INACTIVE`；用户禁用会撤销刷新令牌并让现有 JWT 立即失效；上报和审计保留。
- Demo 安全：重置只允许 Demo 数据集，清理 Demo 业务数据并恢复种子对象状态；Formal 数据请求直接拒绝。
- UI：用户端保持地图优先，上报使用地图选点；管理端障碍列表、地图和审核检查器联动，风险、可信度与状态均有文字表达。
- 文档：新增 `docs/BUSINESS_WORKFLOW.md`，记录可信度、审核、过期、权限和重置规则。

## 人工验收

1. 使用 USER 登录，在“用户服务”查看设施详情，评分、评论并提交一条补充建议。
2. 在“障碍上报”地图选点，提交临时障碍；确认“我的上报”显示 `待审核 / LOW / 尚未生效`。
3. 规划一条路线并收藏，确认历史和收藏页面可见。
4. 使用 ADMIN 进入“治理工作台”，在地图审核区定位上报；审核通过后重新规划，确认路线立即响应。
5. 对测试上报选择实地核验，确认可信度为 HIGH；普通审核不得自行产生 HIGH。
6. 在设施建议页采纳或拒绝建议，在审计日志中确认相应动作。
7. 禁用一个非当前用户，确认其接口访问立即返回 401，再重新启用。
8. 执行 Demo 安全重置，确认 Demo 用户业务数据被清理、种子地图仍存在；不要对 Formal 数据执行任何操作。
9. 缩窄浏览器并切换深色模式，确认地图、底部内容、表格、风险与焦点仍可辨认。
