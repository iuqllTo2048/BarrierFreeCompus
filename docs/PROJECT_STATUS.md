## 已知限制

- Stage 2 不包含 A*、路线计算、GPS、图片/OSS、审核闭环、统计和 AI。
- 当前建筑新增以中心点生成轻量占位多边形；精细建筑轮廓编辑留到后续数据完善阶段。
- GCJ-02 数据使用 PostGIS SRID 0 保存，并由 `dataset.coordinate_system=GCJ02` 和 GeoJSON 元信息声明；绝不伪装为 EPSG:4326/WGS84。
- 高德 Web JS Key 按官方机制属于浏览器可见标识，必须在高德控制台配置域名白名单；安全密钥由 Nginx 代理追加，不进入前端包。
- Docker 会对名称含 `KEY` 的公开 Web JS Key 构建参数给出通用敏感信息警告，这是预期提示；真实值未提交到 Git。
- 本机浏览器控制运行时未能建立自动化连接；视觉交互需按下方人工步骤验收，HTTP/API/构建验证均已完成。
- Node 26 非常规 LTS 风险继续保留；Docker 构建固定使用 Node 22 Alpine。

## 人工验收

1. 打开 `http://localhost:8080/`，分别用 USER 与 ADMIN 演示账号登录。
2. 用户端确认云麓校园底图及建筑、道路、设施、障碍可见，切换系统深色模式并缩窄窗口检查移动布局。
3. 管理端点击“节点”，在地图取点并保存；再选择两个节点创建道路，刷新页面确认数据仍存在。
4. 新增一项设施，使用对象搜索框定位；确认风险信息不只依赖颜色。
5. 导出 GeoJSON 后重新导入当前 Demo；确认提示成功且数量不重复增长。
6. 临时停用数据集，确认用户端不可访问，再立即恢复启用。
